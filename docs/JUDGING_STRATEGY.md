# Judging Strategy

Four equal priorities per the user brief: innovation, impact, implementation, and design (25% each).

| Priority | Evidence to build | Phase 1 contribution |
| --- | --- | --- |
| Innovation | Crowd movement that is instantly readable and encourages teamwork | Product-specific playable rope preview |
| Impact | Real streamer setup and viewer participation | Short setup path; readable commands; honest disconnected state |
| Implementation | Twitch integration, authoritative game loop, robust reconnect | Typed contracts, persistent transport foundation, validation and tests |
| Design | Easy to operate and fun to watch | Original visual system; calm control room and expressive overlay |

Later demo: explain the game, connect a real channel, show viewers moving the rope in Twitch,
resolve a round, demonstrate recovery, and show a concise trace of Codex contributions.
Phase 1 alone is not an eligible complete Twitch-connected submission. Phase 2 adds the actual integration code,
but its real Twitch exit gate is BLOCKED until credentials and broadcaster messages are verified.
Finalist-level ambition still requires real broadcaster testing and the remaining phases.
Official rules became accessible during Phase 2; the brief records that updated evidence.

Phase 5 connects the crowd mechanic to a specific streamer decision: five editable templates, a server-frozen winning choice,
an exact next action, a public commitment and another round. The control room prioritizes the current question and live controls;
its actual OBS preview/result shares that same state. This supplies implementation/design evidence and a concrete impact proposition,
not measured audience adoption or guaranteed judge scores. Current public rules were reopened and still weight the four criteria equally.

The later live demo should show the broadcaster actually taking the winning action in their game. A commitment alone does not
prove that action happened; the product does not claim automatic game control. Real Twitch/native OBS evidence, streamer usability,
long soak and submission preparation remain open. The Phase 5 task stops at the verified local workflow.

Phase 6 removes observed demo friction: winner display names the actual choice, an embedded source keeps its proportions,
small-screen navigation yields space to the game, consent/setup text follows the type roles, and preview art shares the live family.
The audit links identical-size before/after views, labeled simulated motion and regression results. This supports the Design criterion
and makes the intended streamer/community decision easier to demonstrate for Potential Impact. It does not establish improved adoption,
retention, fun, task success or finalist ranking; those require real streamer/viewer evaluation. Real Twitch/native OBS gates remain open.
